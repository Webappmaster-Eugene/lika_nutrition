Проверь собственные изменения так, как их проверял бы придирчивый ревьюер. Автотестов в проекте нет, поэтому этот проход — не формальность, а основная защита от дефекта на проде.

## 1. Определи объём

```bash
git diff              # незастейдженное
git diff --cached     # застейдженное
```

Если diff пуст — возьми список файлов из `$ARGUMENTS`.

## 2. Пять вопросов к каждому изменённому файлу

1. **Корректность.** Делает ли код то, что задумано? Обработаны ли все ветки? Что будет на пустом списке статей, на отсутствующем файле, на несуществующем слаге?
2. **Типы.** Есть ли неявный `any`, `as`, non-null assertion? `null` и `undefined` различаются там, где это важно? Поля frontmatter могут отсутствовать — учтено?
3. **Ошибки.** Что произойдёт при отказе сети, при неверном вводе в форму, при недоступном Telegram? Пользователь увидит внятный текст или тишину? Ошибка проглатывается молча?
4. **Побочные эффекты.** Не ломает ли это соседние секции? Модальное окно закрывается и возвращает фокус? Повторная отправка формы не уходит дважды?
5. **Чистота.** Остался ли мёртвый код, отладочный вывод, лишний импорт, закомментированный блок?

## 3. Специфика этого проекта

- **Статический экспорт.** `next.config.js` задаёт `output: 'export'`. Появился ли в изменениях серверный код — route handler, `middleware.ts`, серверный экшен, `revalidate`, динамический сегмент без `generateStaticParams`? Всё это в такой сборке не работает.
- **SEO.** Новая страница имеет свой экспорт `metadata`? Попала в `src/app/sitemap.ts` — и с трейлинг-слэшем, как требует `trailingSlash: true`? JSON-LD не противоречит тексту страницы?
- **Публичные переменные.** Всё из `NEXT_PUBLIC_*` попадает в клиентский бандл. Не добавилось ли туда что-то, чего посетителю видеть не следует?
- **Клиент против сервера.** `'use client'` стоит там, где реально нужны состояние, эффект или анимация? Каждый такой компонент тянет за собой бандл.
- **Контент.** Тексты, цены и услуги правятся в `src/lib/content/`, а не внутри компонентов.
- **Изображения.** `images.unoptimized: true`: в браузер уедет ровно тот файл, что лежит в `public/images/**`. Новая картинка сжата? Путь существует?

## 4. Найди минимум три улучшения

Даже если код выглядит готовым. Кандидаты:

- имя переменной, которое приходится расшифровывать по контексту;
- условие, которое читается через отрицание отрицания;
- ранний выход (guard clause) вместо вложенности;
- тип, который можно сузить с `string` до литералов;
- сообщение об ошибке, по которому нельзя понять, что делать дальше;
- комментарий, объясняющий «что» вместо «почему».

## 5. Исправь найденное сразу

Не оставляй «на потом» — после правок прогони:

```bash
npm run lint
npm run typecheck
npm run build
```

Сборка здесь заменяет отсутствующие тесты: она единственная проходит по всем страницам и падает на сломанном экспорте. Визуальное изменение дополнительно посмотри в браузере — сборка съехавшую вёрстку не видит.

## 6. Отчёт

- Что нашёл и что исправил — списком, по существу.
- Что осознанно оставил как есть и почему.
- Вердикт: **Ready to commit** или **Needs more work** с перечнем оставшегося.

## 1. Обязательный прогон

```bash
npm run smoke     # lint + typecheck + build, в этом порядке
```

Порядок не случайный: линтер и типы отрабатывают за секунды, сборка — минуты. Запускать сборку первой значит долго ждать, чтобы узнать про неиспользованный импорт.

Если нужно по частям:

```bash
npm run lint
npm run typecheck
npm run build
```

Автотестов в проекте нет. Это значит не «тесты пройдены», а «этой проверки не существует» — так и пиши в отчёте.

## 2. Статический экспорт

`next.config.js` задаёт `output: 'export'`: сборка обязана оставить готовый сайт в `out/`.

```bash
test -d out && ls out | head
test -f out/index.html && test -f out/robots.txt && test -f out/sitemap.xml && echo "SEO-артефакты на месте"
```

- Нет `out/` — нечего выкатывать: `Dockerfile` явно падает на `test -d out`.
- Новая страница есть в `src/app/`, но нет в `out/` — скорее всего она серверная или у динамического сегмента нет `generateStaticParams`.
- Появился route handler, `middleware.ts`, серверный экшен или `revalidate`? В этой сборке они не работают. Это блокер, а не замечание.

## 3. SEO-артефакты

```bash
grep -c "<url>" out/sitemap.xml          # число адресов
grep -o "https://[^<]*" out/sitemap.xml | head -20
cat out/robots.txt
```

- Каждая новая страница присутствует в `sitemap.xml` и **заканчивается слэшем** — в конфиге включён `trailingSlash: true`, расхождение даёт редирект и дубль в индексе.
- Домен в `sitemap.xml`, `robots.txt` и canonical — рабочий. Он приходит из `NEXT_PUBLIC_SITE_URL`; при пустой переменной подставляется дефолт `https://likanutrition.ru`. Собирал без переменной — скажи об этом явно.
- JSON-LD на страницах не противоречит их тексту: выдуманный рейтинг или отзыв в разметке хуже его отсутствия.

## 4. Переменные окружения

- Появилась новая переменная — добавлена в `.env.example`, `docker-compose.yml` **и** в Dokploy UI? Пропуск любого из трёх мест даёт молчаливый дефолт в рантайме.
- `NEXT_PUBLIC_*` прокинута как `ARG` в `Dockerfile`, а не только в `environment`? Она инлайнится в бандл **на этапе сборки**; переданная только в рантайме, в браузере окажется `undefined`. Сейчас так прокинут только `NEXT_PUBLIC_SITE_URL` — новой переменной нужен свой `ARG`.
- В `NEXT_PUBLIC_*` не попало ничего, кроме заведомо публичных значений: всё из этого префикса видно посетителю в исходниках страницы.

## 5. Docker

```bash
docker build -t lika-check .
```

Локальная сборка проходит, а докерная нет — чаще всего расходятся версии Node: в образе `node:20-alpine`, а на машине может быть новее.

Проверять образ целиком:

```bash
docker network create dokploy-network 2>/dev/null || true
docker compose build && docker compose up -d
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3080/
docker compose down
```

## 6. Секреты

```bash
git status --short                       # нет .env, случайных дампов, .idea
git diff --cached                        # в коммите только то, что нужно
grep -rniE "(password|secret|token|api[_-]?key)\s*[:=]\s*['\"]" src/ | grep -v process.env
```

Последняя команда должна возвращать пусто: любое такое значение берётся из `process.env`, не из литерала.

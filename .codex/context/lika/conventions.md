# Соглашения кода

- TypeScript strict. `any` и non-null assertion не использовать: линтер их не
  ловит, поэтому ответственность на авторе.
- Next 14 App Router: серверные компоненты по умолчанию, `'use client'` — только
  там, где реально нужны состояние, эффект или Framer Motion.
- Одинарные кавычки, без точек с запятой, 2 пробела — как в существующих файлах.
- Импорты через алиас `@/…` (объявлен в `tsconfig.json`), а не `../../..`.
- Контент — в `src/lib/content/`, типы — в `src/types/`, чистые функции — в
  `src/lib/utils/`. Не вшивать тексты и цены в компоненты.
- Статьи блога — Markdown в `src/lib/content/blog/` с frontmatter
  `title`, `excerpt`, `date`, `image`, `tags`.
- Новая страница попадает в `src/app/sitemap.ts` с трейлинг-слэшем и в навигацию
  `Header`, иначе её не увидят ни поиск, ни посетитель.
- Метаданные задавать через экспорт `metadata` (или `generateMetadata`), а не
  ручными тегами в разметке. JSON-LD — через `StructuredData`.
- Изображения из `public/images/**`. `images.unoptimized: true`, поэтому размеры
  и вес правит автор, а не оптимизатор Next.
- Комментарии узкие и только «почему». «Что делает» видно из кода.
- Ошибки не проглатывать молча: пользователь формы должен увидеть внятный текст.
- Тексты для пользователя — по-русски, «вы» со строчной, без англицизмов.
- Коммиты: `type(scope): суть по-русски`, в настоящем времени.

# Лендинг Лики Нутрициолог: инструкции Codex

Отвечай по-русски. Работай до проверенного результата, учитывая текущий запрос.
Эти инструкции действуют и при открытии `109.lika-visitka`, и при открытии
Git-репозитория `app`. Определи репозиторий: текущая папка с `package.json` и
`src/` либо её `app/`. Все команды npm/git ниже выполняются из репозитория, не
из родительской папки.

## Контекст и память

Перед изменениями прочитай `.codex/memory/MEMORY.md` и `.codex/context/CLAUDE.md`
относительно репозитория. Последний файл — полная синхронизируемая инструкция
Claude, а не сокращённый пересказ. Для архитектурных изменений дополнительно
прочитай `../expert_info/lika/project.md`, `conventions.md`, нужные `phases/`
и `checklists/`. Если внешние документы отсутствуют, используй копии в
`.codex/context/lika/`. Данные в коде, `package.json` и `next.config.js`
приоритетнее устаревших чисел и путей в документации.

Владелец разрешил локальные изменения, доступы, git-операции и необходимые
инструменты в проекте (2026-09-21). Не спрашивай повторно уже данное разрешение.
Push в `main` запускает выкат Dokploy: до push обязательны `npm run smoke` и
скилл `deploy-check`. Изменения самого прода (перезапуск, деплой, подключение
сети, правка переменных на сервере) требуют подтверждения пользователя. Не
включай чужие изменения в коммиты. Не запускай `force push`/`reset --hard` без
конкретной необходимости и разрешения. Не обходи ограничения управляющей среды.

## Скиллы и инструменты

Проектные скиллы находятся в `.agents/skills/`: `self-review`, `deploy-check`,
`prod-check`, `frontend-design`, `project-harness`. Вызывай их как `$self-review`.
Скиллы-адаптеры читают оригиналы в `.claude/skills/`: это единый источник
методологии. `$ARGUMENTS` в оригиналах означает текущий запрос или переданные
пути, не переменную shell. Недоступный инструмент не означает выполненную
проверку: назови точное ограничение. MCP из `.mcp.json` подключаются локальным
адаптером без переноса секретов в Git.

Роли `.codex/agents/` собраны из `../expert_info/lika/agents` с копией в
`.codex/context/lika/agents`. Делегируй только когда задача независима и это
оправдано; не запускай всех ревьюеров на каждое изменение. Роли наследуют
выбранную модель. Ревьюеры не редактируют проект; findings требуют severity,
confidence и сценария сбоя.

## Качество и зависимости

- Node 20+, TypeScript strict, одинарные кавычки, без точек с запятой,
  2 пробела, импорты через `@/`. `any` и non-null assertion линтер не ловит —
  ответственность на авторе.
- Пакетный менеджер — npm (`package-lock.json`). Другой менеджер в этом
  репозитории не использовать.
- Next.js 14 App Router со статическим экспортом: `next.config.js` задаёт
  `output: 'export'`, `trailingSlash: true`, `images.unoptimized`. Сервера в
  рантайме нет — route handlers, `middleware.ts`, серверные экшены, ISR и
  `revalidate` не работают. Динамический сегмент обязан иметь
  `generateStaticParams`.
- Server components по умолчанию; `'use client'` только при необходимости
  (состояние, эффект, Framer Motion).
- Всё из `NEXT_PUBLIC_*` инлайнится в клиентский бандл на этапе сборки и видно
  посетителю. Телеграм-токен форм уже такой и считается публичным; ничего
  чувствительнее рядом не добавлять.
- Новая страница: свой экспорт `metadata`, строка в `src/app/sitemap.ts` со
  слэшем на конце и ссылка в навигации. JSON-LD не должен противоречить тексту.
- Тексты, цены и услуги живут в `src/lib/content/`, а не внутри компонентов.
  Статья блога — Markdown с frontmatter `title`, `excerpt`, `date`, `image`, `tags`.
- Автотестов в проекте нет: это не «проверки пройдены», а отсутствующая
  проверка. Сквозная проверка одна — `npm run build`, она проходит по всем
  страницам и падает на сломанном экспорте. Визуальные изменения смотри в браузере.
- После изменений выполни self-review и относящиеся проверки: `npm run lint`,
  `npm run typecheck`, `npm run build`. Сборка секретов не требует; но
  `NEXT_PUBLIC_SITE_URL` влияет на `sitemap.xml`, `robots.txt` и canonical —
  проверяешь их, задавай переменную явно.
- `npm run codex:verify` запускает полный локальный набор: тесты harness, lint,
  typecheck и статическую сборку. Для изменения только harness достаточно
  `npm run codex:test`, `npm run codex:doctor` и `npm run lint`.
- Скрипты `convert-docx` и `docker:test` ссылаются на отсутствующие в
  репозитории файлы и не работают. Не чини их мимоходом.

## Завершение и продолжение

В итоговом ответе: результат, выполненные проверки, реальные ограничения.
Долгоживущие факты и исправленные заблуждения записывай в `.codex/memory/MEMORY.md`
со ссылкой на источник и датой. Ход незавершённой задачи — в `.codex/state/handoff.md`:
цель, сделано, следующий шаг, проверки, блокеры. Обновляй перед compaction/остановкой.
Не сохраняй токены, пароли, содержимое `.env` и полные логи в памяти.
SessionStart восстанавливает память, Stop проверяет drift и whitespace; это не
замена проверкам качества. После изменения Claude-инфраструктуры: `npm run codex:sync`.
